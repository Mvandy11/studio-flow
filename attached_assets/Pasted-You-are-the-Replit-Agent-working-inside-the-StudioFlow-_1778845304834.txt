You are the Replit Agent working inside the StudioFlow frontend. Your task is to build the multi-winner admin UI for contests so that an admin can:

- Choose how many winners a contest will have
- Assign payout amounts per place
- Trigger the winner-pull API
- See the winners returned
- Know that no repeat winners are selected

Assume the backend endpoint exists:

POST /api/contests/:contestId/pull-winners

Body:
- eventId
- numberOfWinners
- payouts: [{ placeNumber, payoutAmount }]

────────────────────────────────────────
1. LOCATE ADMIN CONTEST DASHBOARD
────────────────────────────────────────
Find the admin contest pages/components, likely:
- /admin/contests
- /admin/contests/[id]
- components like ContestAdminDashboard, ContestAdminPanel, etc.

Identify the best place to add a "Winner Control" panel for each contest.

────────────────────────────────────────
2. ADD MULTI-WINNER CONFIG UI
────────────────────────────────────────
In the admin contest detail view, add a section:

"Winner Settings"

Controls:
- Number of winners (input or select)
- For each winner:
  - Place number (1, 2, 3, ...)
  - Payout amount (currency or numeric input)

Implement dynamic rows:
- When numberOfWinners changes, adjust the list of places
- Default:
  - 1st: 100
  - 2nd: 50
  - 3rd: 25
  (or leave blank for manual entry)

────────────────────────────────────────
3. ADD "PULL WINNERS" BUTTON
────────────────────────────────────────
Add a button:

"Generate Winners"

On click:
1) Call POST /api/contests/:contestId/pull-winners
   with:
   - eventId (from contest/event context)
   - numberOfWinners
   - payouts array

2) Show loading state while request is in flight.

3) On success, display a list:

- Place #
- Winner userId (or display_name if available)
- Payout amount

────────────────────────────────────────
4. DISPLAY WINNER HISTORY (READ-ONLY)
────────────────────────────────────────
If an endpoint or Supabase query exists to read winner_history (admin-only), add a "Winner History" section:

- Table with:
  - created_at
  - place_number
  - user_id (or display_name)
  - payout_amount

This is admin-only.

────────────────────────────────────────
5. HANDLE ERRORS + EDGE CASES
────────────────────────────────────────
- If API returns no winners (no eligible users), show a clear message:
  "No eligible users remaining. All possible winners have already won before."

- If API returns partial winners (e.g., asked for 5, got 3), show what was successfully pulled and a warning.

- If 403, show:
  "You must be an admin to pull winners."

────────────────────────────────────────
6. OUTPUT SUMMARY
────────────────────────────────────────
At the end, output:
- Components created/modified
- How the admin can use the UI
- Any TODOs remaining
